## 每天怎麼用

1. 開啟 [每日規劃索引](plans/README.md)，查看當月日期。
   [食材 overview](plans/overview.md) 已擴充為100種候選：已回報3種＋本期已排57種＋待後續40種。最初20項日期保留，其餘由2027-01-11起按平日與至少三天觀察重排；不宣稱一歲前完成100種。滿六個月至未滿七個月（2026-11-22～2026-12-21）每天兩餐；全期每餐兩樣，餵食量仍有註記。
2. 先讀 [餵食與安全原則](docs/feeding-guide.md)。新食材依家長指定從 2026-10-30 起安排候選；首次引入只排平日、至少間隔三天，遇週末順延。過敏原候選暫排約六個月起，個別較早引入由兒科評估。當時未滿六個月，須兒科確認適合提前且具準備度才執行；未確認則暫緩並順延。六個月前僅列白天少量一餐，奶類照常。
3. 草稿中所有餐點都須先確認食材適合且已耐受。只有當日「新食材候選」可以是首次接觸；同一天其他食材需已耐受。
4. 新食材後的兩天是重複觀察候選，不是已通過測試。若尚未實際引入、出現不適或觀察未完成，延後後續新食材，使用已耐受食物。
5. 用 [每日紀錄範本](templates/daily-log.md) 複製為 `logs/YYYY-MM-DD.md`，填寫實吃內容與反應。菜單只是計畫，沒有紀錄就不視為吃過。
6. 每週用 [週檢視範本](templates/weekly-review.md) 調整下週，再更新 [食材紀錄](docs/food-log.md)。
7. 用 [每週兩次備餐清單](prep/README.md) 備好冷凍食物：週日晚上備週一～三、週三晚上備週四～日，首批另列10/29。每批有食材、用途、分裝估量與標籤，現調品另外列出；先讀 [冷凍／解凍指引](docs/freezer-prep.md)。

## 內容

- `plans/YYYY-MM.md`：每天一列，包含日期、月齡、最多三個餐點欄位（六月齡只用兩欄）、新食材候選、引入時點理由、每餐合計餵食量與備註。米粥中的米也算一樣食材。
- `plans/overview.md`：食材總數、逐項狀態及每月計畫新增數，由產生器同步維護。
- `prep/YYYY-MM-DD.md`：30週、59批備餐清單（檔名為供餐週的週一），與每日菜單同步產生。
- `docs/freezer-prep.md`：分裝估量、保存、解凍與復熱方式。
- [台灣小兒科醫師與醫院資料查核](docs/taiwan-recommendations.md)：食物範例、建議差異與100種的排程限制。
- [規劃檢視與修正](docs/plan-review.md)：發現的問題、修正與仍待確認事項。
- docs/feeding-guide.md：開始時機、餐次、質地、過敏與噎食原則。
- `docs/food-log.md`：已試過與待引入食材；計畫和實際分開記。
- `docs/sources.md`：CDC、WHO、NHS 的查核來源與適用範圍。
- `templates/`：每日進食及每週採買/檢視範本。
- `.github/ISSUE_TEMPLATE/`：GitHub 每週規劃與食材觀察範本。
- `scripts/generate-plan.mjs`：不需安裝套件，產生日期精確的每日草稿。
- `scripts/expanded-foods.mjs`：77項擴充候選、安全準備方式與時點理由；本期排不下者另列待後續。

## 調整計畫

修改 `profile.json` 後執行；`introductionStartDate` 控制新食材起始日，與規劃起始日及滿六個月日期分開設定：

```sh
node scripts/generate-plan.mjs
node scripts/check-plan.mjs
node scripts/check-prep.mjs
```

**重跑會覆寫 `plans/` 與 `prep/` 中本工具產生的規劃檔與索引。** 實吃與庫存紀錄請放在 `logs/`，不把唯一紀錄寫在自動產生的勾選或庫存欄；工具不會修改logs。開始日期與結束日期使用日曆日期計算。若要修改菜單輪替或新食材候選順序，編輯產生器。

## 建立 GitHub 私人 Repo

本機已有內容後，若使用已登入的 GitHub CLI，可在這個資料夾執行：

```sh
gh repo create nolan-first-foods --private --source=. --remote=origin --push --description "Nolan 一歲前每日副食品規劃與進食紀錄"
```

若 Repo 已存在，先檢查遠端，勿重複建立。此專案含出生日期與可能的健康紀錄，維持私人存取；不放照片、住址或其他不必要的個資。
